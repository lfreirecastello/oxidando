02 · State

Variables are stable by default

let creates a binding. Rust prevents reassignment unless you add mut, short for mutable. This makes possible changes visible to the reader.

Pythonmutable by default
count = 10
count += 1
print(count)
Rustvariables.rs
let mut count = 10;
count += 1;
println!("{count}");
Expected output11

Types can be inferred or written explicitly

Rusttypes.rs
let retries: u32 = 3;  // non-negative integer
let ratio: f64 = 0.75; // floating-point number
let enabled = true;    // inferred bool
let initial = 'R';     // char uses single quotes
let label = "ready";   // borrowed text: &str
Word you just met · shadowing

Writing let again creates a new binding with the same name. Unlike mutation, the new value may have a different type.

Rustshadowing.rs
let input = " 42 ";
let input = input.trim();
let input: u32 = input.parse().expect("a number");
println!("{input}");

03 · Everyday text

Strings, associated functions, and methods

Python has one everyday string type. In Rust, String owns growable text while &str is a borrowed view of text.

Ruststrings.rs
let raw = "  Oxide  ";
let clean = raw.trim().to_lowercase();

let mut message = String::from("Learning ");
message.push_str(&clean);
message.push('!');

println!("{message}");
Expected outputLearning oxide!
Read the punctuation

String::from(...) is attached to the String type; :: finds it there. message.push_str(...) is a method on an existing value, like calling a method in Python.

.len()Byte length

Returns usize; not a Unicode character count.

.trim()Borrow cleaned text

Removes surrounding whitespace without changing the original.

.to_lowercase()Create lowercase text

Returns a new owned String.

.push_str(...)Append text

Changes a mutable String.

.as_str()Borrow as &str

No copy or new allocation.

.parse::<u32>()Try conversion

Returns a result; errors arrive in Module 2.

A vector resembles a Python list, but every element has the same type. The vec! macro creates one conveniently.

05 · Reusable behavior

Functions make types and returns visible

Pythonfamiliar function
def add_tax(price: float, rate: float) -> float:
    return price * (1.0 + rate)
Rusttax.rs
fn add_tax(price: f64, rate: f64) -> f64 {
    price * (1.0 + rate)
}

The last Rust line has no semicolon. It is an expression whose value becomes the return value. A semicolon would discard that value.

06 · Resource responsibility

Ownership decides who cleans up

Every value has one owner. When that owner leaves scope, Rust drops the value. Assignment of a resource-owning value such as String transfers that responsibility.

  1. 01Every value has an owner.
  2. 02There is one owner at a time.
  3. 03Leaving scope drops the value.
Python · aliasesfamiliar references
first = ["Acme"]
second = first
second.append("ready")
print(first)
Rust · movesnames.rs
let first = String::from("Acme");
let second = first;
println!("{second}");
// first is no longer usable

07 · Temporary access

Borrow instead of transferring ownership

A reference uses & and gives temporary access. A mutable reference uses &mut and gives temporary exclusive access.

Rustborrowing.rs
fn byte_count(text: &str) -> usize {
    text.len()
}

fn mark_ready(text: &mut String) {
    text.push_str(" | ready");
}

let mut customer = String::from("Acme");
let bytes = byte_count(&customer);
mark_ready(&mut customer);
println!("{customer} ({bytes} original bytes)");
Expected outputAcme | ready (4 original bytes)
&TShared borrow

Several readers may coexist.

&mut TExclusive borrow

One writer gets temporary exclusive access.

TOwned value

The function receives cleanup responsibility.

Intermediate depth · API design

Accept &str when a function only needs to inspect text. Accept String when it must retain ownership. The signature communicates allocation and lifetime intent to every caller.

Advanced depth · capability model

Treat &mut T as a temporary exclusive capability, not merely a writable pointer. That exclusivity is what lets safe Rust prevent reference and iterator invalidation without a garbage collector.

The compiler prevents a shared view into a String from being used after a mutation could move its buffer. That rule is the focus of the challenge.

Read the conflict, then repair it

This intentionally broken program keeps a shared text view alive while requesting mutable access to the same String. Your task is to reason about where those accesses overlap.

Rust · challenge.rs diagnostic present 
// Intentionally broken: E0502.
// Read challenge.md before editing. No solution is included.
fn main() {
    let mut customer = String::from("Acme");

    let preview = customer.as_str();

    customer.push_str(" | ready");

    println!("Preview: {preview}");
    println!("Payload: {customer}");
}

Required output after your fix

Preview: Acme
Payload: Acme | ready

Constraints

  • Keep preview as a borrowed &str.
  • Print the borrowed preview; do not hardcode it.
  • Mutate and print the same customer String.
  • No clone, allocated snapshot, or unsafe.
