Basic Rust · words before code
  • Enum — one type with a fixed list of allowed forms.
  • Variant — one allowed form, such as Queued or Sending.
  • Payload — data stored inside a variant, such as percent: 40.
  • Pattern — a description of a value's shape that can give names to its inner data.
  • Match arm — one pattern => result branch. Read => as “then produce.”
  • Exhaustive — every possible variant is handled.
  • T — a placeholder for a type. Option<T> means a value of type T may be present or absent.

01 · State modeling

An enum is a closed set of possibilities

Each variant is a valid form of one type, and each form may carry different data. :: selects a variant attached to the enum type.

Rustdelivery.rs
enum Delivery {
    Queued,
    Sending { percent: u8 },
    Delivered(String),
    Failed(String),
}

let current = Delivery::Sending { percent: 40 };
Python bridge

Think of a union of dataclasses. Rust puts every legal shape under one enum and verifies every use without relying on runtime conventions.

Java bridge

This plays the role of a sealed interface with record-like implementations, but Rust declares the complete variant family in one enum.

JavaScript bridge

This resembles objects with a kind field and different payloads. Rust makes the discriminant and payload relationship part of the type.

Word you just met · variant

One named possibility of an enum, such as Queued or Sending { percent }.

Read the construction

Delivery::Sending { percent: 40 } means: “from the Delivery enum, create the Sending variant and store 40 in its percent field.”

02 · Pattern matching

match unpacks data and covers every case

A pattern describes a value's shape. Names inside it bind the carried data. Every arm returns the same result type, making the entire match an expression.

Rustdescribe.rs
fn describe(delivery: Delivery) -> String {
    match delivery {
        Delivery::Queued => String::from("queued"),
        Delivery::Sending { percent } => format!("sending: {percent}%"),
        Delivery::Delivered(id) => format!("delivered: {id}"),
        Delivery::Failed(reason) => format!("failed: {reason}"),
    }
}
For Sending { percent: 40 }sending: 40%

Exhaustiveness turns a changed state model into a to-do list from the compiler. Use _ only when every remaining case truly shares one meaning; a wildcard can hide new variants.

Intermediate depth · refactoring

Adding a variant deliberately breaks every exhaustive decision point. That friction is valuable when those sites encode business rules.

Advanced depth · representation

An enum is a tagged union: a discriminant identifies the active variant, and enough storage is reserved for its largest payload, subject to layout optimizations.

03 · Explicit absence

Option<T> means “a value may be missing”

Some(T) carries a value and None represents absence. An ordinary T cannot silently become null.

Pythonoptional value
def first(items: list[str]) -> str | None:
    return items[0] if items else None
Javaoptional value
Optional<String> first(List<String> items) {
    return items.stream().findFirst();
}
JavaScriptoptional value
function first(items) {
  return items.at(0); // value or undefined
}
Rustoptional value
fn first(items: &[String]) -> Option<&str> {
    items.first().map(String::as_str)
}

04 · Recoverable failure

Result<T, E> exposes success and failure

Ok(T) carries success and Err(E) carries a recoverable error. The signature tells every caller that failure is expected.

Rustconfig.rs
fn parse_port(raw: &str) -> Result<u16, std::num::ParseIntError> {
    raw.trim().parse::<u16>()
}

fn endpoint(raw: &str) -> Result<String, std::num::ParseIntError> {
    let port = parse_port(raw)?;
    Ok(format!("127.0.0.1:{port}"))
}
endpoint(" 8080 ")Ok("127.0.0.1:8080")
Python bridge

Python usually raises an exception. Result instead makes the failure channel part of the returned value and the static signature.

Java bridge

Think of a typed success/error return rather than a checked or unchecked exception. Callers handle it through values and patterns.

JavaScript bridge

JavaScript may throw or reject a Promise. Rust's Result keeps the error path explicit even for synchronous code.

Read the symbol · ?

Extract the success value and continue, or return the compatible error immediately. It propagates; it does not catch.
